## 0. ПРАВИЛА ЧАТА (ВШИТЫ КАЛЁНЫМ ЖЕЛЕЗОМ, ИЗМЕНЕНИЮ НЕ ПОДЛЕЖАТ)
- Qwen присылает ровно одну команду или один файл за сообщение, затем ждёт ответ «готово».
- Комментарии вокруг команды — не более 2 строк до и 2 строк после.
- Формат файла: метка «создать» или «заменить», путь отдельным блоком для копирования, содержимое в блоке кода.
- Файлы присылаются только новым полным содержимым; никаких дописок и правок на месте командами.
- Если запрошен готовый файл для загрузки — присылается только содержимое файла.
- Никаких лишних артефактов в репозитории без прямой команды.
- Порядок работ: интерфейс → GitHub и Amvera → сценарий для OpenCode под командованием Qwen → LLM и база знаний.
- Роли в работе: Андрей — фронтенд и MVP, Open Code — RAG и рутина, Qwen — логика, промпты, UX и приёмка, Алеся — решение по идее и визуалу.
- Боевые инструкции Андрею (Amvera, git, проверки): одно действие за сообщение в формате «Делай так: …», место выполнения указано явно, ожидание «готово».
- Секреты (PIN) не пишутся в чат, репозиторий и скриншоты; единственные места — Amvera env (секрет) и блокнот Product Owner.
- Дополнения (не противоречат правилам): Commit+Push после каждого файла; досье обновляется файлом после каждого закрытого этапа; футер «📊 Заполненность ~X% | Сжатие».
